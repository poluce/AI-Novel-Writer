# 功能 ADR 0002：结构化角色名册作为唯一事实源，角色图谱为只读派生投影

- 状态：已采纳（现行业务规则）
- 领域：人物设定 / 实体数据建模与只读图谱渲染

## 背景

长篇小说人物众多，包含主角、配角、反派、阵营与复杂关系网。早期系统曾尝试将“角色关系图谱 Markdown 文本”直接作为存储实体，并在后续运行时通过正则反向解析提取角色卡。这导致大模型一旦微调排版（如换用列表符号或修改标题层级），反向解析器就会失败，甚至导致整个角色名单被意外清空清零。

## 决策

**角色身份、定位、资料与人物关系，唯一以 SQLite `characters` 表中的结构化名册（Character Roster）为事实源；角色图谱（Character Graph）仅为确定性的只读派生投影。**

1. **结构化名单作为第一公民**：
   * 所有角色的属性（姓名、别名、阵营、重要度、性格、背景、人际关系数组）以结构化 JSON / 关系表直接存储；
   * 新角色生成或修改时，要求模型直接输出结构化数据，严禁通过排版文本逆向猜测。
2. **角色图谱单向渲染（Deterministic Projection）**：
   * 界面上的“角色关系图谱”由结构化名册实时、确定性地计算生成，仅供可视化浏览；
   * 正常运行时严禁从图谱展示文本反向解析角色卡，彻底斩断双向同步带来的数据撕裂。

## 后果与权衡

* **收益**：彻底消除了排版变动导致角色卡解析失败或名单归零的致命缺陷；
* **代价**：创作者无法在角色图谱 Markdown 中自由插入非结构化的特殊手绘排版字符。
