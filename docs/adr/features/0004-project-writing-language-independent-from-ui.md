# 功能 ADR 0004：小说写作语言与应用界面显示语言彻底解耦

- 状态：已采纳（现行业务规则）
- 领域：国际化（i18n） / 创作语言独立性

## 背景

许多写作者习惯在中文界面下创作英文小说，或在英文界面下创作中文小说。若将正文生成与 AI 助手的提示词语言与界面的 `locale` 硬性绑定，会导致创作者切换软件语言时，AI 生成的小说语言被强制篡改。

## 决策

**小说正文写作语言（`writingLanguage`）与 IDE 界面显示语言（`locale`）完全独立解耦。**

1. **界面语言（`locale`）**：仅控制按钮、菜单、表单标签等 UI 界面文案的展示；
2. **写作语言（`writingLanguage`）**：保存在小说的 `novel_config` 中，专门控制正文起草、大纲细纲推演、AI 助手回复与审稿报告使用的语种（支持 `zh-CN` 与 `en-US`）；
3. **切换隔离**：修改 IDE 界面语言绝不污染小说的写作语种；修改小说的写作语言也绝不影响软件界面的菜单显示。

## 后果与权衡

* **收益**：完美支持跨语种严肃创作，消除语种耦合带来的正文乱码与提示词偏差；
* **代价**：所有内部系统提示词与内置工具描述，必须在主进程与渲染层双向维护中英双语对齐模板。
