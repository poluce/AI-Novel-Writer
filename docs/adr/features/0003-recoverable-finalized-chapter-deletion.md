# 功能 ADR 0003：定稿章节安全删除与可恢复投影清理

- 状态：已采纳（现行业务规则）
- 领域：正文生命周期 / 破坏性操作防护与级联清理

## 背景

定稿章节不仅存在于 SQLite 数据库，还衍生出磁盘实体 Markdown 稿件、向量知识库切片、前后文连续性分析索引等多项外围资产。如果允许创作者轻率一键物理删除，极易因为误点造成不可逆丢稿，或因级联清理中断导致向量库残留孤儿垃圾数据。

## 决策

**删除定稿章节采用“先冻结事实、再两阶段登记、外围投影可恢复清理”的严密机制。**

1. **事务内冻结与操作收据登记**：
   * 删除请求直接绑定受控的 `projectId` 与规范化工程根目录（杜绝任何过时的会话租约概念）；
   * 在 SQLite 原子事务中，先冻结草稿 ID、章节号、定稿快照、实体稿目标文件名与知识库切片关联 ID，并在 `chapter_deletion_operations` 表中登记操作凭据，随后才注销正文与元数据事实；
2. **可重试的外围清理**：
   * 实体稿文件与知识库切片的物理移除属于事务外的外部操作，系统持久化记录清理状态；若因文件占用或进程意外退出导致中断，应用在下次打开项目时会自动根据未完成凭据幂等重试清理；
3. **危险操作强确认**：
   * 针对涉及外围关联资产的定稿删除，必须经过显式的人工危险二次确认，绝不执行静默物理粉碎。

## 后果与权衡

* **收益**：最大程度保障创作者资产不被误杀，保证级联索引与本地文件的最终一致性；
* **代价**：删除流程较为严密，不支持无视关联资产的瞬间强删。
