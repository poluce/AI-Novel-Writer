# ADR 0020：助手按作用域分成项目助手与界面助手

- 状态：已采纳（2026-09-15）
- 相关：[0019 Pi 拥有会话存档与上下文压缩](0019-pi-owns-conversation-storage-and-compaction.md)、[0018 Pi 原生工具调用取代文本协议](0018-pi-native-tool-calling-replaces-text-protocols.md)

## 背景

助手原本只有一个：会话列表、界面存档和模型上下文都按项目隔离（`<项目>/.vela/`）。没有打开项目时：

- 面板仍然可以聊，但那是**纯内存**会话——刷新或关窗就没了，磁盘上既没有界面存档，也没有 Pi 会话文件；
- 系统提示词退化成"只有身份、没有项目事实"的降级形态，工具集却仍然是全套项目工具，模型可能去调一个必然失败的工具；
- 一旦打开项目，这个无项目的会话既不会出现在项目存档里，也没有地方可去。

这个状态不是设计选择，而是"存档按项目隔离"留下的缺口。

## 决策

把助手拆成两个**作用域**，用同一套身份与提示词模板，区别只在项目事实、工具集与存档位置：

| | 项目助手（`project`） | 界面助手（`global`） |
|---|---|---|
| 何时可用 | 打开项目后 | 应用打开着就可用 |
| 系统提示词 | 身份 + L0 项目事实 + 技能目录 | 身份 + 技能目录（**不带**项目事实） |
| 工具集 | 全部项目工具 + 技能检查 + MCP | 只保留技能检查（`inspect_writing_skill`）与 MCP |
| 界面存档 | `<项目>/.vela/agent-conversations.json` | `~/.vela/agent-conversations.json`（主进程读写） |
| 模型侧存档 | `<项目>/.vela/agent-sessions/` | `~/.vela/agent-sessions/` |

配套规则：

1. **一次对话只属于一个助手**。会话记录带 `scope`，切换助手只换列表可见范围，不迁移会话。
2. **切换与自动跟随**：打开项目自动切到项目助手；关闭项目自动切回界面助手；右侧面板顶部可手动切换，未打开项目时项目助手不可选。
3. **删除/清空按作用域**：清空只清当前助手的会话与其存档；界面助手的全局会话不会因为"在项目里点了清空"而被删掉。
4. **事件按会话路由**：在途回合按会话 ID 索引，切到另一个助手时后台那一侧的流式输出仍然写进它自己的消息里，不会丢。
5. **`~/.vela` 只由主进程读写**：界面助手的界面存档走新增的 `agent:load/save-global-conversations`，渲染层只收发字符串（与 MCP 配置、`prompts/`、`skills/` 同一条边界）。
6. **工具集按作用域裁剪而不是靠失败兜底**：没有项目时不挂项目读写工具，避免模型调用注定失败的写工具。

## 结果

- 无项目时的对话从此有地方落盘：界面助手会话在 `~/.vela`，可跨项目、跨窗口恢复。
- 项目内的一切仍然跟着项目走，删除或备份项目不会牵动界面助手。
- 系统提示词与工具集和"当前能不能读项目"一致，模型不再看到它用不了的工具。
- 会话文件与界面列表的位置关系变得可判定：**一个助手一份存档根**，不会再出现"界面列表在项目里、会话文件在别处"的孤儿。

## 取舍

- 两个助手共用一份会话列表（用 `scope` 区分），切助手时列表整体换一屏；没有做"两个面板并排"。
- 界面助手不带项目事实，因此它不能回答"这本书第三章写了什么"——那是项目助手的事；需要时用户得先打开项目。
- 界面助手保留 `inspect_writing_skill` 但不挂 `install/bind_writing_skill`：安装与绑定都指向项目内的写作阶段，没有项目时没有意义。
- 历史遗留：升级前在无项目状态下聊过的对话没有落盘，无法迁移（当时就没有存档）。
