# 架构 ADR 0008：创作助手双作用域物理隔离（项目助手与全局助手）

- 状态：已采纳（现行系统基石，继承 0020 并以单数据源收敛）
- 领域：Agent 运行时架构 / 会话作用域与安全沙盒

## 背景

在早期单助手模型下，会话列表与上下文默认绑定当前项目。但在创作者尚未打开任何小说工程时，边栏助手处于无主内存状态，刷新或关闭即丢失，且可能携带项目专属工具（如读写蓝图），诱导模型调用注定失败的接口。

## 决策

**将创作助手严格划分为“项目助手（`project`）”与“全局助手（`global`）”两个互斥且物理隔离的作用域。**

| 维度 | 项目助手（`project`） | 全局助手（`global`） |
| :--- | :--- | :--- |
| **生效场景** | 仅在小说项目打开时可用 | 任何时刻可用（无项目时的常驻助手） |
| **系统提示词** | 注入小说核心大纲、世界观背景、当前角色事实与当前章节上下文 | 仅包含助手基础专业身份，**绝不注入任何特定项目事实** |
| **挂载工具集** | 挂载全套项目级创作工具（小说配置、架构、细纲蓝图、正文草稿等） | 裁剪掉所有项目工具，仅保留技能检查与全局通用扩展 |
| **物理仓储根** | `<项目根>/.vela/agent-sessions/`（随小说工程一同打包迁移） | `~/.vela/agent-sessions/`（全局常驻） |

### 核心隔离军规
1. **会话生命周期互不干扰**：会话实体强制携带 `scope` 标签。在小说项目内清空对话，绝不触碰与删除全局助手的历史记录；
2. **工具集按作用域物理裁剪**：全局助手在挂载时直接剔除所有小说专属 Tool，从源头上杜绝大模型在无工程上下文时调用领域写操作；
3. **仓储单数据源完全收敛**：两类助手统一由 `AgentConversationStore` 驱动，物理落盘于各自独立的 `.jsonl` 会话仓储中，前端完全不持有任何文件写入权限。

## 后果与权衡

* **收益**：彻底消除了无项目时的会话丢失问题，杜绝了大模型在全局状态下误写小说数据的风险；
* **代价**：全局助手无法感知特定小说的情节与人物细节，作者如需推演具体书稿必须打开对应项目。
