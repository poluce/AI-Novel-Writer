# 架构 ADR 0010：技能目录（Skill）按 Pi 原生规范与加载器解析

- 状态：已采纳（现行系统基石，继承 0022）
- 领域：扩展生态 / 提示词技能规范与诊断

## 背景

写作技能（`SKILL.md`）是长篇小说在设定、起草、审稿环节按需注入高级技法的重要载体。早期应用层自行手写简易 frontmatter 解析器，导致多行 YAML 语法错误崩溃、缺少目录名校验、无法识别 `.gitignore` 忽略文件，且一旦语法不规范技能就会静默凭空消失，创作者无法得知安装失败的原因。

## 决策

**彻底废除自研的简易技能扫描器，直接复用 Pi 原生加载器（`loadSourcedSkills` + `NodeExecutionEnv`）完成技能目录的发现、校验与诊断。**

1. **兼容标准 agentskills.io 规范**：
   * 自动支持真实的完整 YAML 语法（折叠块、列表标量）；
   * 自动支持忽略规则（跳过 `.gitignore`、`node_modules` 与点目录）；
   * 严格遵循 `a-z0-9-` 规范命名与目录一致性校验。
2. **规范诊断不丢弃（Diagnostics Transparency）**：
   * 任何技能若存在规范违规或语法瑕疵，系统**绝不静默吞没**；
   * 技能仍保留在系统中，并将 Pi 的底层诊断信息（如命名不匹配、描述超长、YAML 语法错误等）原汁原味呈现在设置界面的“技能目录诊断”中，供作者快速排查修复。
3. **正文按需动态拉取**：
   * 技能正文**不预先打包塞入系统提示词**，系统提示词仅携带简要目录摘要；
   * 当大模型需要调用特定技法时，通过 `load_writing_skill` 动态实时读取磁盘最新内容，兼顾上下文预算与修改即时生效。

## 后果与权衡

* **收益**：技能包生态与官方标准完全接轨，诊断透明度大幅提升，模型上下文消耗显著减少；
* **代价**：诊断信息直接输出 Pi 原生英文规范错误，应用层不做二次转译。
