# 架构 ADR 0001：核心技术栈与本地优先（Local-first）哲学

- 状态：已采纳（现行系统基石）
- 领域：系统基础架构 / 客户端底座

## 背景

长篇小说创作具有高度的个人隐私性、长周期性与资产沉淀特性。许多基于 Web 的 SaaS 写作工具存在数据网络依赖强、离线无法保存、云端宕机丢稿、用户不拥有原始数据所有权等痛点。同时，长篇小说正文编辑（十万至数百万字）对编辑器的排版渲染、行号计算、大文本差异比对以及响应速度提出了严苛的性能要求。

## 决策

**本项目定位为面向严肃长篇小说创作者的“本地优先（Local-first）专业级桌面 IDE”。**

1. **核心技术栈选型**：
   * **宿主环境**：Electron + Node.js。通过主进程与渲染进程分离架构，赋予应用直接访问本地文件系统、执行本地编译原生扩展、运行持久化嵌入式数据库与调度本地模型的能力；
   * **前端展现层**：React 19 + TypeScript + Tailwind CSS。严格遵循类型安全契约，以极简、克制、无视觉噪音的专业 IDE 风格构建界面；
   * **核心编辑器**：CodeMirror 6。深度定制长篇小说排版、段落沉浸、行号计算、双语对齐与正文行内差异 Diff 比对；
   * **工程测试体系**：Vitest 单元测试 + Vitest Browser Mode（基于 Playwright Chromium 的真实浏览器 DOM 测试）。
2. **本地优先原则（Local-First Data Ownership）**：
   * **物理资产绝对归属作者**：创作者的所有小说工程均保存在用户自选的物理文件夹中，数据以本地 SQLite 数据库（`vela.db`）与纯文本 Markdown 形式存放，离线状态下所有编辑、大纲与历史记录完全可用；
   * **零云端数据库依赖**：系统不搭建也不强制依赖任何中心化云端账户数据库，网络通信仅发生在用户配置的 LLM API 鉴权调用与 GitHub Release 更新检查环节。

## 后果与权衡

* **收益**：创作者拥有绝对的数据安全感与所有权，系统启动快、离线全功能可用，彻底消除了云端丢失作品的风险；
* **代价**：多设备同步需交由创作者借助本地网盘（如 iCloud、OneDrive、Git）实现，应用需在跨平台路径与本地文件系统权限边界上付出更多工程防御成本。
