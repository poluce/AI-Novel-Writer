# 架构 ADR 0011：创作助手会话原生化与单一真实数据源

- 状态：已采纳（现行系统基石）
- 领域：Agent 会话存储 / 前后端状态同步与事件溯源（Event Sourcing）

## 背景

在早期的 Pi 迁移阶段中，系统残留了“前后端双轨持久化”的妥协设计：
1. 主进程底层由 Pi Agent 的 `JsonlSessionRepo` 实时追加事件日志（`.vela/agent-sessions/*.jsonl`）；
2. 渲染进程由前端 Zustand `agent-store` 监听状态，通过 400ms 防抖定时器全量序列化所有对话，试图写入 `agent-conversations.json` 充当界面视图镜像。

这种双轨设计引发了严重的架构隐患：
* **定时器并发冲突与数据假丢失**：全局助手与项目助手的防抖定时器互相踩踏（`clearTimeout`），导致项目会话在防抖阶段被频繁误取消。应用重启后前端因盲目读取未更新的 JSON 镜像，造成底层明明有完整记录、界面却空空如也的假丢失；
* **性能浪费与时序阻塞**：大模型打字期间前端频繁执行深度对象的全量 JSON 序列化，且在切书、关窗时为了刷盘不得不发起阻塞性异步等待。

## 决策

**彻底废除前端写盘机制，100% 以主进程底层 Pi Agent 的原生会话仓储（`JsonlSessionRepo`）作为唯一真实数据源（Single Source of Truth）。**

1. **写路径绝对唯一与即时物理落盘**：
   * 创作助手在生成过程中的每一个字、每一轮思考、每一个工具调用与回执，均由主进程 Pi Agent 原生实时追加至 `.jsonl` 文件，天然具备断电抗毁性与零丢失保证；
   * 前端彻底不执行任何磁盘文件写入，完全移除所有防抖定时器（`schedulePersist`）、全量序列化与刷盘代码。
2. **读路径单向化与条目折叠还原（Entry Fold Engine）**：
   * 前端在打开项目或挂载助手时，通过统一 IPC 通道 `agent:list-conversations` 向主进程发起查询；
   * 主进程直接扫描 `repo.list()`，并通过 `foldEntriesToMessages` 将底层的原始事件流（`user`、`assistant`、`toolCall`、`toolResult`）折叠还原为符合界面气泡渲染的标准消息树结构；
   * 查询与还原过程强制执行时间戳与序列号升序（`oldestFirst`），杜绝回溯指针导致的倒序错位。
3. **原生会话标题固化**：
   * 采用 `@earendil-works/pi-agent-core` 原生的 `session.getName()` 与 `session.setName()` 接口，首条提炼标题或重命名标题直接固化至 `.jsonl` 头部，无需外挂配置文件。
4. **生命周期彻底解耦**：
   * 窗口关闭、切书与清空对话不再有任何异步写盘拖拽，应用退出与切换瞬时完成。

## 后果与权衡

* **收益**：
  * 彻底消灭了“底层有数据但界面丢失”的结构性断层；
  * 前端彻底转为无状态视图层（Stateless View Layer），内存占用大幅降低，消除高频打字时的 CPU 与 I/O 抖动；
  * 架构边界高度清晰，主进程专司模型调度与持久化，前端专司交互与呈现。
* **权衡**：
  * 会话列表加载时需要由主进程执行一次底层条目扫描折叠，但由于本地文件 I/O 极快（毫秒级），对于桌面小说创作场景体验零感知。
