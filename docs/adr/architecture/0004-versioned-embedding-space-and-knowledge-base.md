# 架构 ADR 0004：版本化项目嵌入空间与向量索引代际隔离

- 状态：已采纳（现行系统基石）
- 领域：知识库检索 / 向量嵌入引擎

## 背景

在小说创作过程中，知识库（RAG）用于设定集查阅、前文伏笔检索与参考书研习。不同 Embedding 模型的向量维度（如 768、1536、3072）和语义几何空间截然不同。如果用户中途更换了嵌入模型或调整了分块参数，盲目向旧向量表追加新向量会导致余弦相似度计算彻底紊乱，使知识库检索完全失效。

## 决策

**每个小说项目同一时刻只激活一个版本化的嵌入空间，严格按“代际（Generation）”进行物理隔离。**

1. **空间身份强绑定**：
   * 嵌入空间由 `模型标识 + 向量维度 + 距离度量语义 + 索引代际代号` 四元组唯一定义；
   * 严禁将不同维度或不同来源模型的向量存放在同一个集合中混合检索。
2. **平滑代际迁移与零破坏重建**：
   * 当用户切换嵌入模型或调整分块时，系统**绝不执行就地覆盖更新**；
   * 旧代际保持只读并降级为全文检索（FTS5）兜底；新代际在独立的表命名空间中异步构建；
   * 只有当新代际全量向量写入并通过维度与有限数值校验后，才通过原子事务切换为 `active` 状态，彻底杜绝向量数据损坏或检索悬空。

## 后果与权衡

* **收益**：彻底杜绝了模型更换导致的向量空间污染与静默召回率暴跌问题；
* **代价**：在模型切换重构期间，本地磁盘会短暂占用两份嵌入空间的数据体积。
