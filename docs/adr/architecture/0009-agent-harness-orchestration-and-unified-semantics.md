# 架构 ADR 0009：Pi AgentHarness 执行编排与统一采样/写入安全架构

- 状态：已采纳（现行系统基石，整合并演进 0021 与 0023）
- 领域：Agent 执行编排 / 模型参数与写入原子性一致性

## 背景

早期引入 Pi 时，系统仅使用了其底层单轮函数，中间编排（落盘水位、手工压缩、上下文投影、手动确认往返）仍由应用层手写维护，不仅代码冗长，且导致系统出现两条严重割裂的隐患：
1. **采样参数分叉**：同一模型配置，在工作流生成一侧生效了温度与思考预算，但在助手会话中却被静默忽略；
2. **写入安全不一致**：领域工具具备原子写入与提交态回滚保护，而 Harness 自带的底层写操作却缺失该保护，一旦崩溃容易留下半截文件。

## 决策

**将创作助手的多轮生命周期与事件循环 100% 交由 Pi 原生 `AgentHarness` 统一编排，并在生成参数与安全写入语义上实现跨轨道完全统一。**

1. **全面由 `AgentHarness` 接管执行编排**：
   * 废除所有自写的落盘/投影逻辑，挂接 Harness 标准生命周期钩子：
     * `transform_context`：每轮动态注入 L1 编辑器快照与最新系统提示词；
     * `before_tool`：处理领域工具确认卡与执行门禁拦截；
     * `after_tool`：自动执行工具结果截断与写入提交态异常熔断；
2. **跨轨道生成参数完全归一（`resolveGenerationParameters`）**：
   * 无论是一次性工作流生成还是边栏助手多轮对话，温度（Temperature）、推理思考预算（Thinking Budget / Reasoning Effort）均由统一参数策略驱动；
   * 对 Google Gemini 适配器通过 Harness `before_payload` 钩子动态注入真实思考预算，确保全平台思考参数 100% 真正下发给服务商。
3. **统一原子写与提交态安全熔断（Commit State Guard）**：
   * 挂载在 Harness 上的 `write` / `edit` 工具全面接入 `ConfinedExecutionEnv` 的原子写语义（Windows/macOS 走平台安全文件助手，临时文件+原子 Rename）；
   * 写入失败且提交态未知（`unknown`）时，强制终止本轮推理，坚决禁止大模型进行盲目重写，保护作者正文资产。

## 后果与权衡

* **收益**：删除了数百行自研的脆弱编排胶水代码，保证了模型在任意入口下的推理行为与写入安全高度一致；
* **代价**：对无法精确追踪底层行为的 `bash` 执行工具，无法应用文件级原子语义，必须严格交由用户确认卡把关。
