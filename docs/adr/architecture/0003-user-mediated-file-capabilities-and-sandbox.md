# 架构 ADR 0003：用户介导的外部文件授权与路径围栏沙盒

- 状态：已采纳（现行系统基石）
- 领域：系统安全 / 文件系统权限边界

## 背景

在桌面应用中，若允许渲染进程随意传入任意操作系统物理路径直接读写文件，极易遭受注入攻击，并导致大模型误读写宿主操作系统的敏感个人文件。

## 决策

**渲染进程严禁持有任意操作系统物理文件读写权限，所有工作区外文件访问必须经由主进程发放的受限能力凭据。**

1. **用户显式介导授权（User-mediated External Capabilities）**：
   * 导入参考书、导出成稿电子书、自选工程目录等跨越项目边界的操作，必须由用户通过原生操作系统文件选择器（Dialog）显式触发；
   * 主进程统一签发短期、操作受限（只读/单次写）、范围受限（仅目标文件）的授权令牌，渲染层仅凭令牌执行对应操作。
2. **路径围栏与作用域沙盒（Confined Execution Env）**：
   * 项目内所有常规文件操作，路径被严格限制在 `<项目根>/` 内部，主进程通过规范化路径（Canonical Path）与词法审查双重把关，严禁任何 `../` 越界读取；
   * 界面助手的工作区限制在 `~/.vela/workspace/` 与 `~/.vela/skills/`；
   * 任何超出围栏的操作直接在主进程层拒绝，返回权限拒绝错误。

## 后果与权衡

* **收益**：彻底消除了恶意提示词或失控 Agent 窥探、篡改用户操作系统敏感文件的风险；
* **代价**：所有文件操作必须经过主进程鉴权中转，渲染层无法直接调用 Node.js 的 `fs` 原生接口。
