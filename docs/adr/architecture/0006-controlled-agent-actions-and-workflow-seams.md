# 架构 ADR 0006：AI 动作受控 Seam 机制与领域事实写入边界

- 状态：已采纳（现行系统基石，继承 0008）
- 领域：Agent 安全性 / 领域驱动设计（DDD）与提议机制

## 背景

AI 智能体通常具备通用文件操作能力（如 `write_file`、`edit`）。若允许大模型直接向工程目录写入同名 Markdown 文件（如伪造 `characters.md` 或直接覆盖配置），极易绕过业务层校验，造成界面未刷新、SQLite 数据库事实未同步、甚至正文意外丢失的严重灾难。

## 决策

**严禁 AI 智能体绕过领域层裸写数据库或通过通用文件操作篡改小说核心事实。所有领域状态变更必须走强类型的受控 Seam（Proposal & Workflow Seams）。**

1. **通用文件工具仅限产物生成**：
   * 通用工具（`write`、`edit`）写入的文件仅被系统视为“助手游离产物（Artifacts）”，严禁将其视为修改了小说业务事实；
2. **领域事实修改全面走 Submit Tool 与提议通道**：
   * **小说配置**：必须通过 `novel_config`；
   * **故事架构与世界观**：必须通过 `story_architecture`；
   * **章节细纲蓝图**：必须通过 `propose_chapter_blueprint`；
   * **正文草稿生成**：必须通过 `GenerateDraftCommand` 工作流；
3. **前置校验与事务原子性**：
   * 领域工具必须经过 JSON Schema 强类型校验、领域规则校验（`DomainProposal` 构建）；
   * 校验通过后，在主进程通过原子事务写入 SQLite 权威事实表，并通过 IPC 事件总线统一通知前端刷新，保证视图层、数据库与大模型对“操作成功”达成 100% 一致认知。

## 后果与权衡

* **收益**：彻底消除了大模型通过底层文件写入引发的系统状态错乱与数据损坏；
* **代价**：新增小说业务领域时，必须专门编写配套的领域 Tool 与 Schema，无法直接依赖通用命令行搞定。
