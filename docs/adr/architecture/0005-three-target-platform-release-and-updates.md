# 架构 ADR 0005：三目标平台自动化构建、资格验证与更新架构

- 状态：已采纳（现行系统基石，整合并提升 0005 与 0016）
- 领域：持续集成（CI） / 跨平台打包与软件更新

## 背景

AI-Novel-Writer 面向跨平台创作者发布，支持 Windows x64、macOS ARM64 与 macOS x64 三大架构。桌面安装包构建存在环境不一致、体积庞大、平台签名机制差异大等问题。同时，客户端更新如果在后台粗暴自动下载或静默重启，极易中断作者正在进行的正文写作，造成不可逆的丢稿事故。

## 决策

**确立严格的云端同源资格构建流水线，以及尊重创作者工作状态的受控更新交互。**

1. **同源资格构建（Same-SHA Cloud Qualification）**：
   * 正式 GitHub Release 必须严格基于同一个冻结源码 Commit SHA，在 GitHub Actions 官方干净环境中并行独立构建 Windows x64、macOS ARM64 与 macOS x64 三份二进制；
   * 本机不得随意打包并手工上传作为官方发布资产，发布资产严格执行 SHA-256 校验和对齐。
2. **非侵入式平台更新策略（Respectful Update Policy）**：
   * **Windows 端**：检测到新版本时仅显示温和可用提醒；只有创作者明确点击“下载更新”，才启动后台传输；下载完成后，严格侦测当前是否存在未保存文本或正在运行的 AI 生成任务，未保存时绝对禁止强制重启安装；
   * **macOS 端**：仅显示新版提醒并引导创作者访问官方 Release 页面，不擅自在应用内静默替换应用程序，杜绝破坏 macOS 系统的公证安全链。

## 后果与权衡

* **收益**：发布产物具备 100% 可复现性与同源一致性；软件更新永远把创作者的正文安全置于最高优先级；
* **代价**：多平台构建耗费更多的 GitHub Actions 云端 Runner 运行配额。
